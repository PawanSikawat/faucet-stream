### Design highlights
- **Common crate**: Redshift = Postgres wire, so pools are `sqlx::PgPool` built from `PgConnectOptions` (`tls: true`→`sslmode=require`, `false`→`prefer`). `password` credential fully implemented; `iam` / `redshift_data_api` parse but return a typed `FaucetError::Config` "not yet supported" at `build_connect_options`. Both connectors build **lazy** pools in `new()` (offline-safe, no I/O; `check()` is the real `SELECT 1` probe) — this makes the connector `new()` unit-testable without a live cluster.
- **Source**: mirrors the postgres `sqlx` streaming cursor (`row_to_json`, precision-safe numeric binds) plus the databricks incremental pattern (`RedshiftReplication`, `state_key`, `apply_start_bookmark`, `filter_incremental`/`max_value`, `${bookmark}` server-side pushdown + client-side backstop, running-max bookmark on the final page). Overrides `check`.
- **Sink**: `write_strategy: copy` (default) stages each page to S3 (`aws-sdk-s3`/`aws-config`, same pattern as `crates/sink/s3`) as JSONL (`FORMAT AS JSON 'auto'`, default) or CSV (`FORMAT AS CSV` with discovered column order), runs `COPY … IAM_ROLE …`, then best-effort deletes the staged object; `insert` does multi-row `INSERT` (sub-chunked at the 32 767 param cap). `supported_write_modes = [Append]`. All `COPY`/`INSERT` SQL and CSV/JSONL serialization are pure, unit-tested functions with exact-SQL assertions; identifiers use `faucet_core::quote_ident` and string literals are single-quote-escaped.
- **Tests**: extensive `#[cfg(test)]` for config validation, credential resolution, COPY/INSERT SQL builders, CSV/JSONL serialization, bookmark/incremental logic, `resolve_query` bind ordering, dataset URIs. `tests/conformance.rs` = Check 1 (config-schema validity). `tests/integration.rs` = `#[ignore]`d, env-gated (`REDSHIFT_*`) — Redshift has no local container, documented CI-only.

### 3. Assumptions / deviations / needs-a-real-compile

- **Lazy pools in `new()`**: chosen over postgres's eager `connect()` so `new()` does no I/O (offline-testable, and `check()` is the true probe). Requires `PgPoolOptions::connect_lazy_with(options) -&gt; PgPool` (sqlx 0.8, infallible) — verify on first compile.
- **`copy_format` default = `jsonl`** (not CSV): `FORMAT AS JSON 'auto'` maps by column name, handles NULLs/types cleanly, and needs no column discovery — materially more robust than CSV. CSV is fully implemented (column-ordered, RFC-4180 quoted) for users who need it.
- **`INSERT` binds native JSON-typed scalars** (string/i64/f64/bool/null) without per-column `::type` casts. This is best-effort — string→`DATE`/`TIMESTAMP` coercion into typed columns is the one edge that needs live-cluster validation; `COPY` (the default) is the recommended and robust bulk path. Documented in the sink README.
- **`iam` / `redshift_data_api` credentials** deserialize but error at client-build with a clear "not yet supported (v1 = password only)" message, per the v1 scope.
- **Column discovery** uses `information_schema.columns` (Redshift folds unquoted identifiers to lowercase — a known Redshift quirk; mixed-case tables should be created/queried consistently).
- **Conformance** covers Check 1 (config-schema validity) only. Check 2 (bounded-memory) needs a live cluster since Redshift speaks the PG wire (no wiremock path like the HTTP warehouse sources), so it's exercised by the `#[ignore]`d `tests/integration.rs` instead — noted in each conformance file.
- I did **not** add a `cli/examples/*.yaml` (would touch a shared dir and isn't in the file-scope constraint). If desired later, a `redshift`-targeted example plus its `examples/README.md`/CI-validate-list entry would be the follow-up.
