## Summary

Built the **Azure Blob Storage / ADLS Gen2** source + sink connector pair (issue #349) as three new crates using `object_store`'s `azure` feature (the low-risk path — same crate parquet already uses). The connectors are faithful clones of the GCS/S3 object connectors, sharing an `object_store`-backed client builder in a new `faucet-common-azure` crate. All `object_store` 0.13.2 API calls were verified against the vendored crate source (builder methods, `get`/`put`/`list` on `Arc&lt;dyn ObjectStore&gt;` via the `#[async_trait]` base trait, `AzureConfigKey::from_str` aliases, `PutPayload: From&lt;Bytes&gt;`).

Key design points:
- `faucet-common-azure` holds `AzureCredentials` (`account_key`/`sas_token`/`connection_string`/`managed_identity`/`service_principal`/`default`), `AzureConnection` (container/account/auth/endpoint/allow_http/use_emulator), and `build_store()`. Credential resolution is a **pure** `config_entries()` returning `Vec&lt;(&amp;'static str, String)&gt;` mapped onto `MicrosoftAzureBuilder::with_config(AzureConfigKey::from_str(...), v)` — fully unit-tested without a live store.
- **`connection_string`** is parsed into the account/key/sas/endpoint config keys `object_store` actually understands (it has no single connection-string key).
- Source: list `prefix`/`object_keys`, `json_lines`/`json_array`/`raw_text`, `buffer_unordered(concurrency)`, `stream_pages` with `batch_size=0` sentinel, per-object-key compression (`auto`/`gzip`/`zstd`), `Source::check` (bounded list probe), `config_schema`, `dataset_uri` (`az://…`).
- Sink: JSONL blobs, `batch_size`/`max_records_per_file` rollover, UUIDv7 time-sortable keys, compression, `Sink::check`, `config_schema`. Kind string / `connector_name`: **`azure-blob`**.
- **Deliberately out of scope for v1** (noted below): sharding, `discover`, and the GCS/S3 `verify_length`/`verify_checksum` integrity machinery (`object_store` validates content-length on `get`).

## 3. Assumptions &amp; spots that need a real compile

- **`object_store` 0.13.2 Azure API — verified against the vendored source**, not assumed: `MicrosoftAzureBuilder::{from_env, with_account, with_container_name, with_use_emulator, with_endpoint(String), with_allow_http, with_config(AzureConfigKey, impl Into&lt;String&gt;), build}`; `ObjectStore` base trait is `#[async_trait]` (dyn-safe) so `get`/`put`/`list` work on `Arc&lt;dyn ObjectStore&gt;`; `GetResult::into_stream() -&gt; BoxStream&lt;'static, Result&lt;Bytes&gt;&gt;`; `put(&amp;Path, PutPayload)` with `impl From&lt;Bytes&gt; for PutPayload`; `ObjectMeta.location: Path` (Display). The `AzureConfigKey::from_str` aliases used are all present: `azure_storage_account_name`, `azure_storage_access_key`, `azure_storage_sas_key`, `azure_storage_client_id`, `azure_storage_client_secret`, `azure_storage_tenant_id`, `azure_storage_endpoint`. **Two aliases that do NOT exist were avoided**: there is no connection-string key (parsed manually) and `use_azure_cli` is `azure_use_azure_cli` not `azure_storage_use_azure_cli`.
- **`build()` laziness**: I assume `MicrosoftAzureBuilder::build()` performs no network I/O and defers credential validation to request time (matching parquet's lazy `AmazonS3Builder::build()`). The `build_store_succeeds_lazily_*` and `new_builds_lazily_with_emulator` unit tests depend on this; if `build()` eagerly rejects an incomplete service-principal/emulator config, those few tests would need adjusting. Confidence high (mirrors S3).
- **Managed identity**: user-assigned sets `azure_storage_client_id`; system-assigned emits no key and relies on `object_store`'s default credential chain reaching IMDS. Worth a live-backend sanity check but correct per the builder's credential resolution.
- **Integration tests use Azurite** (`mcr.microsoft.com/azure-storage/azurite`) and skip cleanly when Docker is absent; the read/write **assertion** tests are `#[ignore]`d (seeding Azurite needs SharedKey-signed container-create/upload — the analog of GCS's ignored emulator tests), with a non-ignored "builds against emulator" test + a non-ignored conformance "errors, not panics" test that runs unconditionally. Run the ignored ones with `cargo test -- --ignored` against a backend with the container pre-created.
- **Coverage**: pure logic (credential→config-key mapping incl. connection-string parsing, format parsing, key capping, chunk-size/key generation, config serde/builders, compression resolution, batch-size validation, container-empty rejection) is unit-tested inline to hit the ≥90% patch bar; the object-store I/O paths are covered by the ignored Azurite tests.
- **Docs-sync surfaces NOT touched** (per hard constraints — flag for a follow-up in the same PR): `docs/book/src/reference/connectors.md` capability matrix + counts, root `README.md` connector table/counts, a `cli/examples/*_to_azure_blob.yaml` (+ `examples/README.md`), and the crate table in `.claude/rules/architecture.md`. These are the maintenance.md "add a connector" surfaces I could not edit here.
