### `MatrixRow` — `cli/src/config.rs:510-583`

```rust
/// One row of the `matrix:` block.
#[derive(Debug, Clone, Serialize, Deserialize, JsonSchema)]
#[serde(deny_unknown_fields)]
pub struct MatrixRow {
    /// Row identifier. ... Anonymous rows get a synthetic `row-N` id.
    #[serde(default)]
    pub id: Option&lt;String&gt;,

    /// If set, this row runs once per record produced by the named parent row.
    #[serde(default)]

    /// `parent:`, no records are consumed and no per-record fan-out occurs.
    #[serde(default)]

    /// the record. Used as the state-key suffix. Default: `id`.
    #[serde(default = "default_parent_key")]
    pub parent_key: String,

    /// Partial override of `pipeline.source` (deep-merged).
    #[serde(default)]
    pub source: Option&lt;PartialConnector&gt;,

    /// Partial override of `pipeline.sink` (deep-merged).
    #[serde(default)]
    pub sink: Option&lt;PartialConnector&gt;,

    /// Row-level transforms. Appended after `T_pipeline` and `T_source` ...
    #[serde(default)]
    pub transforms: Option&lt;Vec&lt;TransformSpec&gt;&gt;,

    /// When `false`, drops upstream `T_pipeline` and `T_source` transforms
    /// for this row. Default `true`.
    #[serde(default = "default_true")]

    #[serde(default)]

    /// - field absent  → `None`     — inherit from `pipeline.dlq`
    /// - `dlq: null`   → `Some(None)` — disable DLQ for this row
    /// - `dlq: { ... }` → `Some(Some(spec))` — replace base DLQ wholesale
    #[serde(default, deserialize_with = "deserialize_dlq_override")]
    pub dlq: Option&lt;Option&lt;DlqSpec&gt;&gt;,

    #[serde(default)]
    pub delivery: Option&lt;faucet_core::DeliveryMode&gt;,

    #[serde(default, skip_serializing_if = "Vec::is_empty")]
    pub tags: Vec&lt;String&gt;,
```

## 2. How a `parent:` child gets its N invocations at runtime

The whole runtime lives in `run_expanded()` — **executor.rs:216-568** — which runs **level-by-level** (roots = level 0), not a recursive walk.

Data structures:
- `CapturedRecords = Arc&lt;Mutex&lt;HashMap&lt;String, Vec&lt;Arc&lt;Value&gt;&gt;&gt;&gt;&gt;` — **executor.rs:46**. Keyed by node id; holds each parent's emitted records as `Arc&lt;Value&gt;` (pointer-clone hand-off, #160).
- A parent's records are captured by wrapping its sink in a `CapturingSink` (constructed in `run_one_invocation`, executor.rs:1088-1096) and, on success, appended to the map in `run_unit` (**executor.rs:606-617**): `.extend(records.into_iter().map(Arc::new))`. Capture only happens when `capture.is_some()`, i.e. the node has children (see `build_projections`).
- Only the referenced fields are kept: `build_projections()` (**executor.rs:778-817**) computes a `Projection::Full` or `Projection::Paths(...)` per parent from each child's `parent_key` plus its `deferred_refs`. Applied via `project_record` (executor.rs:759).

Per-level fan-out (**executor.rs:334-424**):
1. `ready` = every remaining node whose parent and all `depends_on` are terminal (executor.rs:290-308).
2. `level_records` drains the consumed parents' records out of the shared map (executor.rs:334-347).
3. For a `NodeRole::Child`, it fetches `parent_records = level_records.get(parent_id)` and loops over **each record**, building one `Unit` per record (**executor.rs:387-423**). Empty parent output → child skipped (executor.rs:392-398).

The per-record context map passed to interpolation is built in **`run_one_invocation`, executor.rs:1037-1044**:

```rust
if let (Some(record), NodeRole::Child { parent_id, .. }) = (parent_record, &amp;node.role) {
    let ctx: HashMap&lt;String, Value&gt; = HashMap::from([(parent_id.clone(), record.clone())]);
    resolve_inplace(&amp;mut source_cfg, &amp;ctx)?;
    resolve_inplace(&amp;mut sink_cfg, &amp;ctx)?;
    if let Some(scope) = cleanup_scope.as_mut() {
        resolve_inplace(scope, &amp;ctx)?;
    }
}
```

So the ctx map shape is `{ parent_id =&gt; full_parent_record_json }` — a single entry keyed by the parent's row id. `resolve_inplace` (a local helper in executor.rs that walks strings calling `interpolate_record`) is what expands `${parent_id.dotted.path}` per record. Note `${now.*}` is resolved *before* this, on every invocation, via `resolve_now_inplace` (executor.rs:1015-1016).

Concurrency model (executor.rs:444-461): all units of a level are spawned into a `tokio::task::JoinSet`; each task first `sem.acquire().await` on a shared `Arc&lt;Semaphore&gt;` (executor.rs:228, size `max_concurrent` = config or `default_concurrency()` clamped 1..=8, executor.rs:207-212). Roots and children share the one budget.

## 4. RESERVED_IDS and reserved interpolation-id prefixes

`RESERVED_IDS` — **expand.rs:27-37**:

```rust
pub const RESERVED_IDS: &amp;[&amp;str] = &amp;[
    "env", "file", "secret", "matrix", "pipeline",
    "now", "backfill", "param", "partition",

```

Enforced on row ids at **expand.rs:307-309** (`CliError::ReservedRowId`). Duplicate ids → `DuplicateRowId` (expand.rs:310-313).

Reserved runtime/deferred interpolation ids (not parent-record refs) are handled specially in three places:
- **`check_refs`** (expand.rs:1122-1159) is where an unknown `${id.path}` is rejected. It uses `iter_directives` + `classify_directive` (interpolate.rs). For a `Directive::Deferred { id, .. }`: `param` → hard error (never-bound, expand.rs:1135-1144); otherwise if `id != "now" &amp;&amp; id != "backfill" &amp;&amp; id != "partition" &amp;&amp; !id_set.contains(id)` → `CliError::UnknownInterpolationId` (expand.rs:1145-1155). `env`/`file`/`secret` never reach here because with a colon they classify as `LoadTime` and are already resolved.
- `check_refs` is called over every row's source/sink config and the pipeline-level source/sink/sources/sinks (expand.rs:370-394).
- `collect_deferred` (expand.rs:1220-1240) skips `now`/`backfill`/`partition` so they aren't treated as parent-record deps; everything else becomes a `DeferredRef`.
- `reject_runtime_tokens` (expand.rs:1168-1181) rejects *any* deferred token in transform/state/dlq configs — runtime `${...}` tokens are only legal in source/sink configs.

The classification rule itself is `classify_directive` — **interpolate.rs:250-258**: colon → `LoadTime { prefix, body }`; else split on first `.` → `Deferred { id, path }`.

## 5. Where a runtime "run a source, project a field, dedup" step hooks in

Two existing precedents build+run a source with **no sink** — both are your best hook models:

1. **`faucet discover`** — `cli/src/commands/discover.rs` (this is the closest existing thing to your feature, issue #211). `run()` at discover.rs:19-110 does: `build_source(&amp;spec.kind, spec.config.clone(), &amp;auth, None)` (discover.rs:39-40), checks `source.supports_discover()`, then `source.discover().await` to enumerate datasets, filters them (`filter_datasets`), and **generates a config with one matrix row per dataset** (`render_discovered_config`, discover.rs:80). That is fan-out over discovered values, but resolved *ahead of run* into static rows, not at runtime.

2. **`faucet preview`** — `cli/src/commands/preview.rs:54-77`: `build_source(...)` then `let records = source.fetch_all().await?;`, applies transform stages, takes `args.limit`, prints. No sink.

3. **`reconcile::run`** — `cli/src/reconcile.rs:123-139`: the canonical minimal "build a source, drain it, extract a field" pattern:

```rust
let source = crate::registry::build_source(&amp;spec.count.kind, spec.count.config.clone(), auth, None).await?;
let records = source.fetch_all().await?;
let authoritative = extract_count(&amp;records, spec.count.count_field.as_deref())?;
```

The underlying primitive is the `Source` trait — `crates/core/src/traits.rs:12-48`:
- `fetch_with_context(&amp;self, context: &amp;HashMap&lt;String, Value&gt;)` (traits.rs:20) — the primary method; **this is exactly the context-map contract your discovery step could feed**, same shape as the executor's per-record `ctx`.
- `fetch_all(&amp;self)` (traits.rs:26) — convenience with empty context.
- `stream_pages(...)` (traits.rs:73) for paged draining.

Field projection uses `resolve_dotted(root, path)` (interpolate.rs:328-344), and the executor's `resolve_parent_key` / `walk_value` (executor.rs:671-681, 720-730) are the dotted-path readers you'd mirror. There is **no existing dedup helper** — you would add that.

Assessment: the executor does *not* currently have a runtime "enumerate a value-set from a source then fan out rows over it" step. The per-parent-record fan-out (executor.rs:387-423) is the structural analog: it takes a `Vec&lt;Arc&lt;Value&gt;&gt;` and emits one Unit per element. A discovery-driven matrix would most naturally either (a) resolve to static rows before the run like `discover` does, or (b) introduce a new pre-level in `run_expanded` that runs discovery sources (via `build_source` + `fetch_all`), projects+dedups values, and synthesizes `Unit`s the way the child branch does — feeding the cross-product into the same `ctx` map / `build_state_key` machinery. The Unit-per-element loop and `CapturedRecords` are your templates; a cross-product would multiply several such value-sets before building units.

## 6. How `depends_on` completion-ordering interacts with `parent:`

They are **orthogonal and combinable** — a node can have both.

- **Expand-time**: `parent` and `depends_on` are validated independently. Parents: single-parent-chain cycle check `detect_cycle` (expand.rs:1045-1065). `depends_on`: unknown-dep / self-dep checks + per-row dedup preserving order (expand.rs:343-364). Then the **combined** graph is checked with **Kahn's algorithm** in `detect_combined_cycle` (**expand.rs:1073-1117**): for each row, `prereqs = parent (if any) ∪ depends_on`, computes in-degrees, topo-sorts; any unprocessed node → `CliError::DependencyCycle`. This is why a cycle routed *through* a `depends_on` edge can't deadlock the executor.
- The BFS `order` that `expand()` emits (expand.rs:410-418) is built from the **parent** graph only (roots first, then children breadth-first) — `depends_on` does **not** affect emission order; it is enforced purely at runtime.
- **Runtime readiness** (`run_expanded`, **executor.rs:290-308**): a node is `ready` only when BOTH hold:
  - parent is terminal: `Root =&gt; true`, else `completed.contains(parent_id) || skipped_subtrees.contains(parent_id)`;
  - AND `node.depends_on.iter().all(|d| completed.contains(d) || skipped_subtrees.contains(d))`.
- **Difference in semantics**: `parent:` hands off records (the child fans out once per parent record, consuming `level_records`); `depends_on:` is pure completion-ordering — no records consumed, no fan-out (see the module doc, executor.rs:13-17, and `MatrixRow.depends_on` doc, config.rs:522-527).
- **Skip cascade**: if a parent failed/was skipped, the child subtree is skipped (executor.rs:352-358); if any `depends_on` prerequisite failed/was skipped, the node is skipped too (executor.rs:363-374). Both cascade into `skipped_subtrees`. Readiness only asks "is there anything left to wait for"; whether a terminal prereq *skips* the node is decided in the unit loop.

A node with both `parent: p` and `depends_on: [d]` therefore fans out per record of `p` **and** waits for `d` to fully complete first; readiness requires both terminal, and a failure of either skips it.

## Column mapping — `SchemaTranslator` (`core.py:1129`), `denormalized: true`
Denormalized = **one flat top-level BQ column per top-level JSON-schema property** (`Denormalized.preprocess_record` → `translate_record`, `core.py:960`; contrast fixed-schema mode which wraps everything in one `data` JSON column). Column names run through `transform_column_name`.

**`schema_resolver_version: "2"`** (`_jsonschema_property_to_bigquery_column`, V2 branch lines 1244–1294): far more lenient than V1 — **falls back to `JSON` for anything unresolvable** instead of erroring. Behavior:
- `anyOf` → uses index [0]’s type/format.
- **array**: no `items`/no item `type`/`patternProperties` → `JSON REPEATED`; item type record → `RECORD REPEATED`; else scalar `&lt;type&gt; REPEATED`.
- **object**: no `properties`, empty `properties`, or `patternProperties` present → **`JSON NULLABLE`** (whole object stored as a JSON value); otherwise recurse into a `RECORD` with nested fields (`_translate_record_to_bigquery_schema`, line 1298 — empty props → `JSON`).
- **scalar**: `patternProperties` → `JSON`; else `bigquery_type()`.
- On **any exception** → `JSON NULLABLE` (with a table/field-name special-case in `IGNORE_JSON_FIELDS_FOR_TABLES` → `STRING`).

So nested objects **with a declared schema** become native BQ `RECORD` (STRUCT); schemaless/dynamic objects and arrays-of-unknown become `JSON`; arrays of scalars/records become `REPEATED`. (For these taps most objects are pre-flattened/typed, so expect mostly scalar columns + a few RECORD/JSON.)

**Type map — `bigquery_type` (`core.py:1498`)**: `format:date-time`→`TIMESTAMP`; `date`→`DATE`; `time`→`TIME`; `number`→`FLOAT`; `integer`+`string`→`STRING`; `integer`→`INTEGER`; `boolean`→`BOOLEAN`; `object`→`RECORD`; **else `STRING`** (default/unknown). All scalar fields land `NULLABLE`.

**`column_name_transforms.add_underscore_when_invalid: true`** — `transform_column_name` (`core.py:1524`): strips backticks; removes Unicode whitespace/control/zero-width chars; **if first char is a digit, prepends `_`** (the "add_underscore_when_invalid" behavior); replaces `.`→`_` (`replace_period_with_underscore` is force-set True in translation, lines 1156/1167); and **always** replaces special chars `[!@#$%^&amp;*()/,]`→`_`. Note: `lower`/`snake_case` are **not** enabled by this config, so column casing is preserved as-is from the tap (only the invalid-char/leading-digit fixes apply). The function is `@cache`d.

## sharepointsites (repo: DrivetrainAi/tap-sharepointsites, fork of storebrand/radbrt)

- **Source system / category:** Microsoft SharePoint document libraries — file-based ELT (spreadsheets/CSVs stored in SharePoint sites), finance/ops flat files.
- **Mechanism (EXACT):** File-over-Microsoft-Graph. The `FilesStream` talks to `https://graph.microsoft.com/v1.0`: resolves site→drive (`/sites/{host}:/{type}/{name}:` → `/sites/{id}/drive`), fetches file metadata by item-id (`/drives/{driveId}/items/{fileId}`), then **downloads the raw file bytes** via `@microsoft.graph.downloadUrl` (or `/items/{id}/content`) and parses them client-side. It does NOT use the Graph Excel/workbook API. **File formats downloaded+parsed: CSV** (streamed line-by-line into `csv.DictReader`, `csv_handler.py`) and **Excel .xlsx/.xls** (downloaded whole, parsed with **openpyxl** `read_only`, `excel_handler.py`). JSON is not a parsed format here. `client.py` also supports `lists` (Graph SharePoint list REST, `$.value[*]`) and `pages` (Graph beta pages), but the meltano config only drives `files`. Cite: `client.py`, `file_stream.py`, `file_handlers/{csv,excel}_handler.py`.
- **Auth:** `mode: sharepoint` → **Azure AD app-only** via `azure.identity.ClientSecretCredential(tenant_id, client_id, client_secret)` requesting scope `https://graph.microsoft.com/.default`; wrapped in `BearerTokenAuthenticator`. Least-privilege `Sites.Selected` model (per-site admin grant). Cite: `client.py::authenticator`.
- **Pagination:** `GraphHATEOASPaginator` follows `@odata.nextLink` for list/folder responses; individual file downloads are single-shot streamed GETs (Range-limited for schema discovery, 5 MB prefix). Cite: `client.py`, `file_stream.py`.
- **Streams:** Dynamic, **one Singer stream per file** enumerated from an **S3 config JSON** (`{"tables":[...]}`) by `meltano_taps/sharepointsites/pre.py`, which rewrites `meltano.yml`'s `files:` list. Each entry carries `file_pattern`(=`idAtSource` item id), `file_type`, `site_url`(=env `TAP_SHAREPOINTSITES_API_URL`, one URL for all files), `sheet_name`/`sheet_id`, and optional `dataFormatType`. Excel with a `sheet_id` becomes stream `name__{sheet_id}`. No parent→child fan-out. Cite: `pre.py`, `tap.py::discover_streams`.
- **Incremental/replication:** Effectively **full-refresh** (target `overwrite: true`). The tap has a soft filter — `parse_response` skips files whose `lastModifiedDateTime &lt;= starting replication value` (defaults `1900-01-01`) — but no replication_key is emitted; each run re-downloads and re-parses.
- **Record shaping in the tap:** Heavy. CSV→DictReader rows; Excel→openpyxl with **column-type inference** (scans rows → integer/number/boolean/date/date-time/string) and JSON-Schema build; column names normalized (`normalize_name`, optional `snakecase`/`clean_colnames`); `#REF!`/error cells blanked to null; empty-row cutoff (1000); `_loaded_at` stamped. **`data_format_type: timeseries` (Excel only) UNPIVOTS** a wide period-header sheet into long `(dimensions…, Month=date, Value=number)` records — a genuine reshape/denormalize done inside the tap. Cite: `excel_handler.py::_timeseries_rows`, `file_stream.py::stream_schema/parse_response`.
- **Parity risk:** **High.** Requires Graph file download + **openpyxl Excel parsing** with per-column type inference, the **timeseries unpivot transform**, CSV streaming, S3-driven dynamic stream generation, and Range-based bounded schema discovery. A Rust reimplementation must reproduce the Excel semantics (openpyxl date typing, error-cell blanking, unpivot math) exactly to match downstream tables.

## onedrive (SAME repo: tap-sharepointsites; config differs)

- **Source system / category:** Microsoft OneDrive (personal/business) — same file-based ELT tap, different Graph drive + auth.
- **Mechanism (EXACT):** Identical code path (`FilesStream` over Graph `v1.0`), but drive resolution branches on hostname: for `onedrive.live.com`/`*-my.sharepoint.com` it uses **`/me/drive`** and `/me/drive/items/{id}` (+ name/search fallback `/me/drive/root/search(q=…)`), downloading + parsing the same **CSV / Excel(openpyxl)** formats. Cite: `file_stream.py::get_drive_id/_resolve_download_url/_search_file_in_onedrive`.
- **How the two meltano configs differ (key ask):**
  - `sharepointsites/meltano.yml`: `mode: sharepoint`, config = `client_secret` + `tenant_id` (+ `client_id`, `api_url` via env) → **ClientSecretCredential app-only auth**. `pre.py` sets each file's `site_url` from a **single env var** `TAP_SHAREPOINTSITES_API_URL` and **does** propagate `dataFormatType` (timeseries).
  - `onedrive/meltano.yml`: `mode: onedrive`, config = `refresh_token` + `client_secret` (+ `client_id`) → **refresh-token OAuth2** (`POST https://login.microsoftonline.com/common/oauth2/v2.0/token`, `grant_type=refresh_token`, scope `.default offline_access`; MS rotates the refresh token). `pre.py` sets each file's `site_url` from a **per-file `file_info["url"]`** and in practice omits `dataFormatType` (ENG-84395). No `tenant_id`/`api_url`. Both otherwise share `pre.py` logic, target-bigquery `overwrite`/`denormalized` config, and postgres state backend. Cite: `client.py::authenticator` (both branches), both `pre.py`, both `meltano.yml`.
- **Auth:** delegated **OAuth2 refresh-token** flow against the `common` tenant (see above). A companion `_post_refresh_token_helper` pattern persists rotated tokens (used by deskera too).
- **Pagination / Streams / Incremental / Shaping / Parity:** same as sharepointsites (dynamic per-file streams from S3 config, full-refresh overwrite, CSV/Excel parse + optional timeseries unpivot). Parity risk **High**, same reasons.

## afas (DrivetrainAi/tap-afas)

- **Source system / category:** AFAS Profit / AFAS Online (Dutch ERP/HRM) — ERP REST source.
- **Mechanism (EXACT):** **REST-JSON** over ProfitRestServices. Base `https://{environment_id}.rest.afas.online/ProfitRestServices` (or `base_url` on-prem). Records from `GET /connectors/{connector}` under `$.rows[*]`. Cite: `base.py`, `streams.py`.
- **Auth:** Custom header **`Authorization: AfasToken &lt;base64(token-XML)&gt;`** built from a config `token` (accepts full XML, its base64, or hex `data`). Cite: `auth.py::build_afas_auth_header`.
- **Pagination:** `skip`/`take` query params; advance `skip` by `take` until a short page (`AfasSkipTakePaginator`; AFAS gives no reliable total). Cite: `base.py`.
- **Streams:** **Dynamically discovered** — `GET /metainfo` lists every GetConnector → one stream each (or restricted via `connectors` config), name-deduped. No parent→child. Cite: `tap.py::discover_streams`, `streams.py::discover_all_connectors`.
- **Incremental/replication:** **Full refresh only** (`replication_key = None`; target `overwrite: true`).
- **Record shaping:** Schema per stream from `GET /metainfo/get/{connector}` field defs (AFAS datatype→JSON type), else sampled from one row, else passthrough `_raw`. `post_process` JSON-stringifies nested dict/list, Decimal→float, and normalizes date fields against the schema. Cite: `streams.py::fetch_connector_schema`, `base.py::post_process`.
- **Parity risk:** **Low.** Plain paginated REST-JSON; the only nuances are the AfasToken header, metainfo-driven dynamic streams, and X-Profit-Error decoding.

## acumatica (DrivetrainAi/tap-acumatica)

- **Source system / category:** Acumatica Cloud ERP — ERP REST source (OData-flavored contract-based endpoints).
- **Mechanism (EXACT):** **REST-JSON with OData query semantics.** Base `{instance_url}/entity/Default/{version}`; each entity is a path (`/Account`, `/Bill`, …). Uses **OData params** `$top`, `$skip`, `$orderby`, `$filter` (`ge datetimeoffset'…' and … lt …`), and **`$expand`** for nested detail (Details, Contacts/Address, etc.). Records from top-level JSON array `$[*]`; every scalar is `{"value":X}`-wrapped and unwrapped. Cite: `base.py`, `streams.py`.
- **Auth:** **Cookie-session login** (not OAuth): `POST /entity/auth/login {name,password[,company,branch,locale]}` → `Set-Cookie`, sent as `Cookie` header; `POST /entity/auth/logout` at exit; auto **re-login on HTTP 401** (`RetriableAPIError`). Cite: `auth.py::AcumaticaSession`.
- **Pagination:** Custom **`WindowedReplicationPaginator`** — tiles `[bookmark..now]` into **calendar-month windows**, `$skip`-pages within each window, walks empty leading windows. Keyless (static) streams fall back to plain `OffsetPaginator`. This exists to defeat Acumatica's non-strict `$orderby` skip-gap record loss (ENG-77809). Cite: `base.py`.
- **Streams:** **Static, curated** set of 11 (`streams_to_discover` selects; `*`=all): account, bill, currency, customer, financial_period, invoice, journal_transaction, journal_transaction_detail, payment, stock_item, vendor. **Parent→child fan-out:** `journal_transaction_detail` is a singer-sdk child of `journal_transaction`, emitted from the parent's `$expand=Details` via an in-process `_details_cache` keyed by `(BatchNbr, Module)` — **no extra API call**. Cite: `streams.py`.
- **Incremental/replication:** Document streams (bill/customer/invoice/journal_transaction/payment/vendor) are **incremental** on `LastModifiedDateTime` (singer-sdk max-bookmark, non-strict-sort tolerant; target `upsert: true` + `dedupe_before_upsert`). Static dimensions (account, currency, financial_period, stock_item[`LastModified`]) are **full-table, no replication_key** (deliberate, ENG-79419). Cite: `streams.py` docstrings, `meltano.yml`.
- **Record shaping:** `unwrap_value` on `{value:…}` wrapping; nested arrays/objects JSON-stringified (schema-aware: empty dict/list→null, non-string-typed nested→null to survive BigQuery load); child detail rows re-stamped with BatchNbr/Module. Cite: `base.py::post_process`, `streams.py`.
- **Parity risk:** **Medium-High.** OData `$filter/$orderby/$skip/$expand`, the **month-window paginator** (correctness-critical), cookie-session auth with 401 re-login, and the parent-cache child stream all need faithful reproduction; the `{value:…}` unwrap + nested-null coercion is load-bearing for downstream schema.

## deskera (DrivetrainAi/tap-deskera)

- **Source system / category:** Deskera Books (SMB accounting) — accounting REST source.
- **Mechanism (EXACT):** **REST-JSON.** Base `https://api.deskera.com/v1` (`api_base_url`). Two shapes: **list endpoints** (`/account`, `/account/group`, `/contacts`, `/dimension`, `/journal`) and **date-windowed report endpoints** (`/account/reports/gl|trial-balance|pnl|balance-sheet|cash-flow`). Cite: `base.py`, `streams.py`, `reports.py`.
- **Auth:** **Deskera OAuth2 V2 refresh-token.** `DeskeraTokenManager` does `POST {token_url}?grant_type=refresh_token&amp;refresh_token=…` with **Basic** `client_id:client_secret`; access token sent as **`x-access-token`** header. Rotated refresh token written to `/tmp/refresh_token.txt` and persisted by `deskera/post.py` (`_post_refresh_token_helper.update_refresh_token` → drive API). Cite: `auth.py`, `post.py`.
- **Pagination:** List streams: **page-number** paginator (`page`/`limit`, stop on short page, `MAX_PAGES` guard). Report streams: `SinglePagePaginator` per window. Cite: `base.py::DeskeraPageNumberPaginator`, `reports.py`.
- **Streams:** **Static** set of 8 (`streams_to_discover`, empty=all). **Parent→child fan-out:** `account_subgroups` partitions **one request per account-group `code`** (fetched from `account_groups`) via `/account/group/subgroup/{group_code}`. Cite: `streams.py`.
- **Incremental/replication:** **Full refresh** (`replication_key = None`; target `overwrite`). Report streams iterate **month (or day) date windows** from `start_date`→now (`windows.py`) as a fetch strategy, not a bookmark. Cite: `reports.py::request_records`, `windows.py`.
- **Record shaping:** `extract_records` unwraps list envelopes (`LIST_RECORDS_KEYS`). **`journal` is denormalized** — header fields merged onto each line item (`_journal_lines` across several possible line-array keys), `customField` JSON-stringified. **Report streams do NOT normalize** — raw payload preserved wholesale as `report_json` string + window metadata (dbt normalizes downstream). Cite: `streams.py::JournalStream.parse_response`, `reports.py::parse_response`.
- **Parity risk:** **Medium.** OAuth refresh + token rotation persistence, per-group child partitioning, the journal header/line denormalize, and the date-windowed report fetch loop (with `report_json` passthrough) all need replicating; report schemas are provisional.

## dualentry (DrivetrainAi/tap-dualentry)

- **Source system / category:** DualEntry (modern AI accounting/ERP) — accounting REST source (API v2).
- **Mechanism (EXACT):** **REST-JSON.** Base = `API_BASE_URL` (`/public/v2/...`). Standard list endpoints return `{"items":[...],"count":N}` (records `$.items[*]`). Cite: `base.py`, `streams.py`.
- **Auth:** **API key** in header **`X-API-Key`** (`APIKeyAuthenticator`); the key itself is obtained out-of-band via DualEntry's `POST /public/v2/oauth/token` exchange. Cite: `base.py::authenticator`, README.
- **Pagination:** **Offset/limit** (`DualEntryOffsetPaginator`: `offset += limit`, `limit` capped 100, stop on short page). Cite: `base.py`.
- **Streams:** **Static, ~43 streams**, one per top-level list endpoint (schemas hand-defined under `schemas/`; `streams_to_discover` opt-in). **Parent→child fan-out (two patterns, no singer parent_stream_type — each stream self-contained for xiphos-V2 one-task-per-stream):**
  - `DualEntryLineItemStream`: lists parents, then issues **one `{path}/{number}/lines/` request per parent record**, stamping parent ids onto each line (`parent_key_map`), normalizing `line_type` item/expense→items/expenses. (Reflects July-2026 API change: lines no longer embedded.)
  - `DualEntryChildStream`: re-lists parent endpoint(s), takes the **cartesian product** across path levels (e.g. fixed-asset × depreciation-book), fetches parent-scoped child paths returning **bare arrays** (`$[*]`), stamps parent ids. Cite: `base.py::DualEntryLineItemStream/DualEntryChildStream`.
- **Incremental/replication:** **Full refresh** (no `replication_key`; `start_date` reserved for future incremental; target `overwrite: true` + `cluster_on_key_properties`). Cite: `base.py`, README, `meltano.yml`.
- **Record shaping:** `convert_to_string` JSON-stringifies flagged nested fields; line/child rows merged `{**line, **parent_fields}` (parent ids win, feed composite PKs); custom retry/backoff (`_get_json`/`_list_all`) for the manual sub-requests. Cite: `base.py`.
- **Parity risk:** **Medium.** Core listing is trivial offset REST, but the **per-parent line-item fan-out** (N+1 requests, parent-id stamping into composite keys) and the **cartesian-product child streams** are the reimplementation hazards; get the key-stamping wrong and dedupe/upsert silently collapses lines.
