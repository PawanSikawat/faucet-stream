**Design highlights**
- `faucet-common-clickhouse`: `ClickHouseConnection` (`url` **or** `host`+`http_port`+`tls`, `database`, `user`/`password`; `Debug` masks password), `base_url()`, `build_client`, `query_params`, `apply_auth` (`X-ClickHouse-User`/`X-ClickHouse-Key` headers — never URL params), `parse_json_each_row`/`build_json_each_row`, and injection-safe `sql_literal`.
- Source: streams the `JSONEachRow` response body via `reqwest` `bytes_stream()` with a line-buffering decoder (safe across chunk boundaries), `batch_size` pages, incremental `ReplicationMethod` with `@bookmark` server-side pushdown (as a safe SQL literal) + client-side filter backstop, `state_key`/`apply_start_bookmark`, `Source::check` (`SELECT 1`), `config_schema`. Output format set via `default_format=JSONEachRow` setting (no SQL mangling).
- Sink: batched `INSERT INTO &lt;quoted_table&gt; FORMAT JSONEachRow` (statement in the `query` URL param, NDJSON in the body), `async_insert`/`wait_for_async_insert` toggles, `batch_size` re-chunking, identifier-quoted table (via `faucet_core::util::quote_ident`, per-segment for `db.table`), `Sink::check` (non-mutating `SELECT 1`), `config_schema`. Append-only — upsert documented as engine-dependent (`ReplacingMergeTree`), not emulated.
- **Coverage**: extensive unit tests on all pure logic (NDJSON encode/decode, URL/settings builder, `sql_literal` incl. injection cases, line-splitter across chunks, bookmark/incremental filter, config validation, state-key derivation, table quoting, insert-params). `check()` I/O covered by offline connection-refused tests (`127.0.0.1:1`). Integration tests (`tests/integration.rs`) are env-gated on `FAUCET_TEST_CLICKHOUSE_URL` and skip cleanly when absent — no hard network dep.

## 3. Assumptions &amp; spots that warrant a real compile

- **ClickHouse HTTP insert shape**: statement in the `query` URL param + NDJSON in the body is the standard ClickHouse pattern; a live integration run (`FAUCET_TEST_CLICKHOUSE_URL`) confirms the concatenation behaves. The sink integration test does exactly this.
- **`tokio` features**: both crates declare `tokio = { workspace = true, features = ["time"] }` in `[dependencies]` (needed for `tokio::time::timeout` in `check`) — required for the feature-isolation CI matrix, per the "declare crate features for isolation CI" convention.
- **Identifier quoting**: ClickHouse accepts ANSI double-quoted identifiers, so `faucet_core::util::quote_ident` (double-quote) is used, split per `.`-segment so `db.table` → `"db"."table"`.
