## tap-rippling

**1. Base URL** — Literal constant: `https://api.rippling.com/platform/api`. (Token endpoint is on a different host — see below.)

**2. Auth** — **OAuth2 refresh_token grant** (`RipplingOAuthAuthenticator`):
- Token endpoint: **`https://api.rippling.com/api/o/token/`** (POST).
- Client credentials go in an `Authorization: Basic base64(client_id:client_secret)` header (via `meltano_utils.auth.build_basic_auth_header`), `Content-Type: application/x-www-form-urlencoded`.
- Body: `grant_type=refresh_token`, `refresh_token=&lt;config.refresh_token&gt;`.
- The returned `access_token` is applied as the bearer on API calls; `expires_in` drives refresh timing.
- **Refresh-token rotation**: Rippling rotates the refresh_token on *every* refresh, so `update_access_token` writes the new `refresh_token` to `/tmp/refresh_token.txt` (`REFRESH_TOKEN_FILE`) for the next ECS run to pick up. Config keys: `client_id`, `client_secret`, `refresh_token`.

**3. Pagination** — **Offset/limit**, opt-in and conditional (only one stream). In `Employees.get_next_page_token`: if `page_size &lt;= 0` (the default `0`) → single unpaginated request (returns `None`). If `page_size &gt; 0`: params get `limit=page_size` and `offset=next_page_token`; the next token = `previous + page_size`, and it stops when a returned page has `&lt; page_size` records (or isn't a list). No cursor field — pure offset arithmetic.

**4. Per-stream endpoints** — **Only one stream**, `employee`:
- Path: `/employees/include_terminated` (→ `https://api.rippling.com/platform/api/employees/include_terminated`), GET.
- Params: always `send_all_roles=true`; plus `limit`/`offset` when paginating.
- Records JSONPath: **`$.[*]`** (top-level array). (Base class default is `$.results[*]`, but Employees overrides to a bare array.)

**5. Incremental/replication key** — **None.** `primary_keys=["id"]`, no replication key. Full refresh.

**6. Non-trivial mechanics:**
- **Refresh-token rotation persisted to a file** across runs — a generic OAuth2-refresh source that doesn't write the rotated token back would break on the second run (Rippling invalidates the old refresh_token).
- Response standardization: recursive **camelCase→snake_case** key rename, dict flattening (with `ignore_keys=["work_schedule"]` preserved as nested), and timestamp cleanup (`fix_timestamp_keys` strips the `+00:00` offset by splitting on `+` for `created_at`/`updated_at`).
- **Not** catalog/discover-driven — despite being a Singer tap, streams are a static list of exactly one (`Employees`); no dynamic endpoint discovery. `page_size` is a workaround for Rippling's ~60s gateway timeout on large unpaginated pulls.

Filter (`get_url_params`, :185): lower bound `SysModifiedDateTime gt {start}` (from bookmark/`start_date`) **AND** an upper bound `SysModifiedDateTime lt {fetch_start_time}` — `_fetch_start_time` is captured at sync start (:288) so the window is closed and stable, preventing rows written mid-run from moving the bookmark past unread data. Timestamps rendered `%Y-%m-%dT%H:%M:%SZ`.

**6. Not reproducible by a generic REST source** — this tap is the most complex:
- **Source `$count` reconciliation**: after each stream it fetches OData `$count` over the exact sync filter and compares against distinct-PK count extracted; a shortfall beyond tolerance (`source_count_recon_tolerance_pct`, floored at 100 rows) raises `SilentTruncationError` and fails the tap (recon.py) — guards against offset-paging silently truncating a full-table overwrite. Configurable enforce/exclude/tolerance knobs.
- **Concurrent partitioned key-range extraction** (`partitioned_streams`): for FULL_TABLE single-integer-PK streams, discovers `(min,max)` PK via `$orderby+$top=1`, asserts no rows fall outside the window, tiles `[low,high)` into N half-open ranges, fetches them across a `ThreadPoolExecutor` (per-thread `requests.Session`) with a bounded queue for backpressure, and reconciles each key-window against `$count`. Emission stays serial; any range that fails/never-reports aborts so a partial snapshot can't overwrite a good table.
- **EDMX `$metadata` discovery** at `/data/$metadata` with a dedicated 429/Retry-After retry budget (honours HTTP-date or delay-seconds).

    resource_owner_key=self.config["token_key"],

## tap-adp

**Mutual TLS: client cert + key attached at the `requests` layer via `cert=(...)`.** The cert material arrives base64-encoded in config (`cert_public`, `cert_private`), and `TapADP.__init__` materializes them to disk on startup:

## tap-redshift
